### 1.2 分层架构

```
┌─────────────────────────────────────────────────────┐
│  app (组合根 + 入口)                                 │
│  main.py | composition_root.py | container.py       │
├─────────────────────────────────────────────────────┤
│  presentation (表示层 - PySide6/MVVM)                │
│  views/ | view_models/ | services/ | qt_output       │
├─────────────────────────────────────────────────────┤
│  application (应用层 - 用例编排 + 端口)               │
│  session_manager | text_reflow | ports/ | use_cases/ │
├─────────────────────────────────────────────────────┤
│  domain (领域层 - 纯数据模型 + 规则)                  │
│  geometry | exceptions | models/                     │
├──────────────┬──────────────────────────────────────┤
│  vision       │  ocr_runtime                         │
│  (OpenCV 适配) │  (RapidOCR/Fake 引擎)                │
├──────────────┴──────────────────────────────────────┤
│  infrastructure (基础设施)                           │
│  camera_source | sqlite | tts | threading/           │
└─────────────────────────────────────────────────────┘
```

**依赖方向严格单向**（import-linter 强制）：
- `domain` 零外部依赖（不引用 cv2/PySide6/sqlite3 等）
- `application` 不引用任何适配器实现
- `presentation` → `application` → `domain`
- `app` 是唯一组装依赖的位置（组合根）

### 1.5 线程模型

```
主线程 (Qt Event Loop)
  ├── QWidget 操作（唯一合法线程）
  ├── Signal/Slot（QueuedConnection 跨线程安全）
  └── 用户输入处理

相机采集线程 (camera-capture)
  ├── cv2.VideoCapture.read() 循环
  ├── LatestFrameBuffer（容量 1，最新帧优先）
  └── 通过回调 → ViewModel Signal → QueuedConnection → 主线程

OCR 工作线程 (ocr-worker)
  ├── 有界队列（容量 2），满则丢弃最旧
  ├── 同步调用 engine.recognize()
  ├── CancellationToken 取消支持
  └── 结果通过回调 → ViewModel Signal → QueuedConnection → 主线程

人脸提醒线程 (face-alert-worker)
  ├── Haar 检测 + 节流播报
  └── TTS 通过独立线程非阻塞播报

配置加载/保存线程 (daemon)
  └── 同步 SQLite 读写（threading.Lock 保护）
```

**关键设计决策：**
- **全部使用同步方法**：相机枚举/启动、OCR 识别、配置加载均用同步调用，避免 asyncio 事件循环在沙箱/嵌入式环境的兼容性问题
- **QueuedConnection**：所有可能从后台线程发射的 Signal 均使用 `Qt.QueuedConnection`，确保 slot 在主线程执行
- **threading.Event**：相机线程用 `Event` 而非 `bool` 标志位，保证 happens-before 语义
- **threading.Lock**：SQLite 连接虽 `check_same_thread=False` 但所有操作加锁

### 1.6 会话状态机

```
NoInput → LivePreview → Frozen → Recognizing → Result
                                              ├── ReadingView (成功)
                                              ├── ErrorRecovery (失败)
                                              └── BackToOriginal (取消)
```

**过期结果保护**：`SessionId + FrameId + RequestId + FrameRevision` 四元校验，新材料/重新冻结后旧结果自动丢弃。

### 2.1 设计目标

将 PC 原型验证通过的软件闭环迁移到低成本嵌入式终端，实现：
- **全离线**：零网络依赖，模型随包分发
- **低成本**：整机 BOM ≤ ¥250
- **可复现**：BOM + 接线图 + 系统镜像全开源
- **可迁移**：Domain 层零外部依赖，可原样移植到 ARM Linux

## 第三部分：关键设计决策 (ADR)

### ADR-001: 选择 Python + PySide6 而非 WPF/.NET
- **背景**：团队 Python 生态熟悉、开源 OCR 方案丰富
- **决策**：Python 3.13 + PySide6 + OpenCV + RapidOCR
- **理由**：开发效率高、ONNX Runtime ARM64 可直接迁移嵌入式、PySide6 跨平台
- **后果**：性能略低于 .NET 原生，但 CPU 推理足够；打包体积较大

### ADR-002: 全同步调用，不依赖 asyncio 事件循环
- **背景**：asyncio 事件循环在 Windows 沙箱和嵌入式 Linux 兼容性差
- **决策**：相机/OCR/TTS/配置全部使用同步方法，后台线程 + QueuedConnection
- **理由**：消除事件循环创建/清理的兼容性问题，简化线程模型
- **后果**：异步端口保留为 Protocol 定义，实现委托同步方法

### ADR-003: 相机多后端枚举 (MSMF → DSHOW → 默认)
- **背景**：Windows 10/11 下 CAP_DSHOW 后端可能返回空列表
- **决策**：枚举和启动时依次尝试 CAP_MSMF、CAP_DSHOW、默认后端
- **理由**：最大化相机兼容性
- **后果**：枚举时间略增，但用户体验更稳定

### ADR-004: QueuedConnection 防跨线程崩溃
- **背景**：相机/OCR 后台线程发射 Signal，DirectConnection 导致 slot 在后台线程执行 QWidget 操作
- **决策**：所有可能从后台线程发射的 Signal 连接均使用 Qt.QueuedConnection
- **理由**：确保 slot 在主线程执行，避免跨线程 Qt 控件访问
- **后果**：帧显示有微秒级延迟，但稳定性大幅提升

### ADR-005: Domain 层零外部依赖，可原样移植嵌入式
- **背景**：需要从 PC 迁移到香橙派 ARM Linux
- **决策**：domain 包不引用 cv2/PySide6/sqlite3/numpy 等任何外部库
- **理由**：迁移时核心逻辑零改动
- **后果**：import-linter 强制守护，domain 文件只能用纯 Python 标准库
